Structure

系统结构：前后端分离

界面层只发出请求；后端服务由两个智能体与两类结构构成

Structure

三类数据、四个界面与两个智能体

三类数据互相独立，都可直接送入四个界面；四个界面共用两个智能体

Contract

绘图管线的结构化输入与输出

不是自由文本进出：左端是结构化请求，右端是结构化结果与不可变图版本

Contract

报告与幻灯片：另一套结构化文档数据

复用同一套内容块，差别只在组织方式：报告按章节，幻灯片按页

Flow

一次请求的执行路径

六步都在后端完成，前端只通过事件流观察进度

Model

数据与版本模型

只读数据集 - 可复用统计中间态 - 不可变图版本

Limitations

局限与不足

以下为当前已知的边界与未展开的方向

  • 在 UI 上，本次只做了 plot 的常规设计，交互设计没有展开；Workspace 仍是传统的「图形 + 参数面板」形态
  • Canvas 是对更优雅交互范式的一次探索，但它更适合复杂流程，与本场景不匹配，不推荐使用
  • 在 C2R 中，图已经由 abio-agent 产出；对比之下，plot-agent 的使用场景与存在必要性仍需论证（若未来并入 C2R 平台，最终的绘图界面如何存在）
  • plot-skills 尚未部署，后续可以接入
  • 缺少第 5 个界面：组图。由文本驱动的智能体自动选图，按 A4 等版面尺寸编排，之后仍可由绘图智能体继续修改
  • 组图若抽象为后端能力，可作为 Report 的输入，从而让 Report 更好
Outlook

未来展望

两条相互独立的方向

方向一

插件化

四个界面可作为 C2R 平台的插件，官方提供最佳实践，用户也可以参与。

方向二

结果交付

模块的结构化结果可直接生成报告。

Summary

总结

已交付两个绘图向界面与两个高层可视化界面

  • 两个绘图向界面：Workspace 与 Canvas
  • Workspace 支持由智能体返回的自动可调参数
  • Canvas 支持图结构式的编辑方式
  • 两个高层可视化界面：Report 与 Slides
